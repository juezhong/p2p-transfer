# p2p-transfer 文件访问与传输安全（草案）

## 安全边界

- 所有认证、端到端加密、ICE 穿透、QUIC 会话、身份与诊断归 `p2p-sdk`；Transfer 使用经过认证的 SDK Session，不自行跳过证书/密钥检查。
- 经信令服务器配对不等于授权远端访问文件。自动信令服务永不接收/转发业务数据。
- **远端文件系统操作必须独立授权**：读、写、列目录、允许的共享根目录和覆盖行为均需显式、可配置；默认采用最小权限。
- 为保持旧用户行为，合法绝对路径可在显式授权范围内使用，而非默认允许整个机器上任意绝对路径。

## 核心威胁与防护

| 威胁 | 防护要求 |
| --- | --- |
| 未经信任设备请求文件 | 拒绝，配对身份绑定授权 |
| `..`、绝对路径越权、符号链接逃逸 | 按 OS 实现权限边界、目录句柄与路径解析检查 |
| 文件覆盖、同名目录冲突 | 明确用户策略；默认确认或拒绝 |
| 非法 RPC、巨大 JSON/帧、无界目录 | 严格长度/数量/速率上限，超时和资源配额 |
| 重复/延迟文件块污染后续文件 | 独立 transfer/file ID、offset 和状态校验 |
| 分块重排窗口无上限 | 有界缓冲和反压 |
| 中途中断留下误报成功的文件 | `.part`、SHA-256、成功前明确提交流程 |
| 取消/故障导致 worker 泄漏 | 取消后等待退出、超时及资源回收 |
| 诊断泄露 IP、路径和连接码 | 默认脱敏，导出须确认范围 |

## 文件完成的语义

区分 `received`、`written`、`flushed/synced` 和 `committed`。应用级累计 ACK 应明确采用连续写入确认，最终完成需根据目标平台执行约定的 sync/rename 操作并校验 SHA-256。不可把“QUIC Stream 写成功”当成文件落盘。

## 审查要求

模糊测试协议、文件路径边界与元数据；将 Linux/macOS/Windows 的符号链接/junction/reparse point 路径逃逸纳入测试。提交审查必须包含对应测试 ID。

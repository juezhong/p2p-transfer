# Rust p2p-transfer 手工验收大纲与操作用例（v0.1）

> **未来手测指引，不代表目前有可执行版本。** 命令和 GUI/TUI 控件名称均为建议/示意，待实际实现后根据 `--help` 更新。用户可以按本文件逐项测试并反馈结果。

## A. 测试准备和环境记录

准备两台物理机 A/B（可用一台机上两进程做冒烟，但不能取代双机/NAT 测试）。每台记录：
- 系统、CPU 架构、Rust Transfer/SDK 版本和 commit、网络运营商/路由器型号。
- IPv4 是否双 NAT/CGNAT、双方是否有可路由 IPv6、路由器防火墙配置、PCP/NAT-PMP/UPnP 是否启用。
- 信令模式（manual / signaling-only）、STUN 服务器配置和对端身份验证方式。
- 共享目录根、远端只读/读写权限配置、可用磁盘空间和预期文件数量。
- 测试时间；脱敏日志和可复现命令；连接失败时导出 SDK 诊断。

### 数据集（建议每次复用一套）

- D00：`empty.bin`，0 B。
- D01：`hello.txt`，ASCII + 结尾换行（小文件）。
- D02：`中文 文件 name 🚀.txt`，UTF-8 名字且含空格；Windows 不支持的文件名要另测拒绝。
- D03：`random-1m.bin`，1 MiB 随机数据。
- D04：`random-128m.bin`，128 MiB 随机数据。
- D05：`random-2g.bin`，2 GiB 随机数据（仅长测）。
- D06：`tree/`，至少 3 层目录，含空目录、中文路径、同名文件、多个小文件。
- D07：包含需显式确认覆盖的既有目标文件。
- D08：只读/无权限目录、目标磁盘空间不足、符号链接/Windows junction、恶意相对路径。
- D09：源文件传输期间被改写或删除，用于验证文件快照/错误检测策略。

数据 SHA-256 由操作系统标准工具生成、保存为 manifest；Windows 可用 PowerShell `Get-FileHash -Algorithm SHA256`，Linux 可用 `sha256sum`，macOS 可用 `shasum -a 256`。每次传输后比较目的文件 hash 和长度，目录要逐文件比对树清单。

## B. 手工用例清单

### TC-001：首次手动配对（FT-16，SDK）
**前置**：A/B 已安装同版本，配置各自共享根；两者同 LAN，允许 UDP。
**步骤**：A 创建连接得到 INVITE；B 加入粘贴 INVITE 并生成 REPLY；A 输入 REPLY；双方检查对端身份信息和连接状态；查看 `status` 或 GUI/TUI 诊断。
**预期**：双方安全建立连接；显示实际 IPv4/IPv6、候选对及 transport；不需自建信令服务器；无文件操作即不创建传输任务。

### TC-002：错误与过期凭据（FT-16，安全）
**步骤**：重复使用过期连接码；修改一个随机字符；尝试提供与已确认指纹不一致的对端；尝试重新播放过去的邀请。
**预期**：拒绝且给出明确可读错误，不降级明文；日志不打印完整 token/密钥。

### TC-003：上传与下载（FT-01）
**前置**：双方已连接，读写权限已授权。
**步骤**：A 上传 D01 到 B，使用 B 端列目录确认存在；B 再下载回本机另一位置；比较长度、SHA-256。
**预期**：PUT/GET 均成功，双方内容完全一致，进度最终 100%，无残留 `.part`。

### TC-004：空文件、边界大小和大文件（FT-01、08、13）
**步骤**：重复 TC-003，使用 D00、D03、D04；可追加大小跨 chunk 边界的文件。
**预期**：0 B 正确提交，所有大小验证通过，内存不会随着文件大小无限增加。

### TC-005：递归目录和空目录（FT-02）
**步骤**：传输 D06 `tree/`，两端比较目录树、各文件大小与 SHA-256；双向再传一次到新目标根。
**预期**：层级完整、空目录存在、所有文件内容正确，目录总进度不把整个目录大小显示成单个文件大小。

### TC-006：路径 Unicode、空格、绝对路径（FT-04/05）
**步骤**：上传和下载 D02，测试带空格的目录路径，测试被授权的绝对路径；CLI 测试 Tab 补全和正确引用；TUI/GUI 用文件浏览器选择。
**预期**：合法路径均成功；不会拆错文件名或显示乱码；越权绝对路径被拒绝。

### TC-007：远端/本地目录浏览（FT-03）
**步骤**：使用 `pwd`、`ls`、`cd`、`lpwd`、`lls`、`lcd` 及返回父目录/前一目录；在 TUI/GUI 中完成相同浏览。
**预期**：目录切换、展示、错误处理正确；无权目录不暴露敏感信息。

### TC-008：覆盖、冲突及无权限目标（FT-02、09）
**步骤**：将 D01 写入已有不同内容的 D07；分别选择拒绝/明确允许覆盖；再写入无权限目标。
**预期**：遵从覆盖配置，拒绝时原文件无损；写入失败没有标记成功或留下假完整文件。

### TC-009：取消进行中的文件（FT-07）
**步骤**：传输 D04/D05 达到中段时，CLI 使用取消指令或 Ctrl-C；TUI/GUI 点击取消；不退出 P2P 会话，执行 status/目录命令。
**预期**：传输停止，临时文件按约定清理；控制会话仍可用，可继续启动新传输。

### TC-010：双向抢占与单任务租约（FT-06）
**步骤**：A 正在上传 D04，B 同时发起另一个 GET/PUT；A 随后取消/完成，B 重试。
**预期**：第二个任务得到“当前有传输”及占用方向信息；租约释放后可再发起，不能进入双端死锁。

### TC-011：数据链路损坏后恢复（FT-10/11/12）
**前置**：SDK 已提供多 data-only QUIC（后期里程碑），D05，开启受控故障注入。
**步骤**：传输期间关闭一条 data lane，观察其它 lane、SDK 链路恢复、control `status`、最终文件 SHA-256；重复两次。
**预期**：主控制连接不被单数据链路故障带走；数据恢复后未确认块被重传，文件最终完整，worker 无卡死。恢复失败时报告错误而非无限等待。

### TC-012：文件校验失败（FT-08/09/12）
**步骤**：在测试桩/故障注入环境中模拟损坏的文件块、错误摘要或文件内容变化。
**预期**：绝不把 hash 不匹配文件提交为完成品，返回明确校验错误并清理或隔离临时文件。

### TC-013：资源受限（FT-09/13）
**步骤**：传输 D04 至剩余空间不足目标或无权限目录；进行大目录数量压力测试；观察内存/RSS 与取消响应。
**预期**：有界缓存、明确容量错误、无损目标已有文件、无永久孤儿任务或资源泄漏。

### TC-014：CLI 交互和自动化（UI-01）
**步骤**：验证命令帮助、交互操作、命令解析（含 Unicode/空格）、非交互上传/下载、退出码、正常 Ctrl-C 与异常 EOF。
**预期**：命令行为稳定；脚本可通过退出码判断成功失败；传输取消不直接终止正常会话。

### TC-015：TUI 全功能（UI-02）
**步骤**：打开双栏本地/远端目录；用键盘导航、浏览、选择文件/目录、上传/下载、查看进度、取消、查看诊断。
**预期**：核心功能与 CLI 等价；终端缩放/输出日志不破坏 TUI 状态；正常恢复终端。

### TC-016：GUI 全功能（UI-03）
**步骤**：从桌面程序手动配对，选择共享根，浏览双端文件；双向传输目录，进度/取消/错误/诊断；关闭窗口时处理未完成任务。
**预期**：和 CLI/TUI 使用相同 core，操作结果一致；UI 卡顿不阻塞通信；有明确关闭/取消提示。

### TC-017：诊断一致性（FT-15）
**步骤**：在 CLI/TUI/GUI 查看同一连接的实际路径（地址族、ICE 选中 candidate pair、QUIC UDP 端点、失败原因）；导出脱敏 JSON。
**预期**：三界面信息一致、敏感凭据被隐藏、不含完整会话 token。

### TC-018：IPv4/IPv6 LAN 与 NAT（FT-16/17）
**步骤**：在 IPv4-only、IPv6 可达、IPv6 防火墙、同 LAN、不同行政网络两侧 NAT 依次重复 TC-001 + TC-003。
**预期**：满足条件时优先 IPv6；IPv6 不可用回退 IPv4；可达 NAT 直连成功；无法直连时明确报告失败、不使用中继。

### TC-019：自动信令与离线手动模式（FT-17）
**前置**：可选 Rendezvous 服务功能已完成。
**步骤**：A/B 通过 signaling-only 服务交换 ICE 信息，连接后关闭信令服务并继续文件传输；重新测试手动连接码无此服务。
**预期**：服务端仅交换控制信息，不承载文件内容；手动模式不依赖自建服务器。

### TC-020：2 GiB PUT/GET 长传输与 Go 参考（FT-11/13/14）
**步骤**：生成 D05；在同一台设备/网络条件下多次用 Go v0.16.4 与 Rust 各自运行 PUT/GET；记录 wall time、MiB/s、CPU 和最大 RSS。先 loopback，再 LAN 双机；不以 Go/Rust 互通为测试方式。
**预期**：Rust 文件完整、进程稳定、缓冲有界；性能升降客观记录，未经设定阈值与对照验证不宣称“更快”。Go 发布说明的同机 ABBA 数值不可直接当成不同环境的验收阈值。

### TC-021：异常重启与资源回收（FT-07/09）
**步骤**：传输中 SIGTERM/强制结束发送进程；重启后重新连接、列目录、重传；检查 `.part`、端口和后台进程。
**预期**：按设计报告不完整任务、未完成文件不被误当成功；SDK/应用退出后无永久遗留资源。

### TC-022：路径越权与符号链接（安全）
**步骤**：从远端请求 `../`、越过共享根的绝对路径、父目录符号链接、指向机密文件的符号链接；Windows 追加 junction/reparse point。
**预期**：越权被拒绝，无共享目录外文件泄漏/覆盖；合法授权路径仍能访问。

### TC-023：非对称网络与 UDP 封锁（SDK）
**步骤**：A 支持 IPv6、B 仅 IPv4；随后双方模拟 UDP 入口/出口阻断及严格 NAT；抓包或查看诊断。
**预期**：有 IPv4 共同路径时可连接，禁止所有直连路径时 `NoDirectPath`；不偷偷进入 server relay。

### TC-024：兼容性边界（协议）
**步骤**：Rust 新版两个不同能力等级的客户端协商；再尝试使用 Go 版 `P2PF-INVITE/REPLY` 或反向输入新码。
**预期**：Rust 内部能力协商成功或清晰拒绝不兼容能力；Go 旧版互操作被明确拒绝，不产生错误的认证成功。

### TC-025：大批量小文件与文件竞争（FT-02/13）
**步骤**：创建上千小文件目录，包含深层目录与空目录；传输期间源文件被删改、目标目录被其它程序修改。
**预期**：完整性/权限异常能被识别，成功文件 hash 一致；内存与文件句柄有上限；不会覆盖共享根外内容。

### TC-026：多平台发布包验证（UI-01/02/03）
**步骤**：在 Linux amd64/arm64、Windows amd64、macOS amd64/arm64 运行官方二进制；检测 CLI/TUI/GUI 启动、双端上传下载、诊断和退出。
**预期**：支持平台正式发布时三种 UI 都有可用交付方式；无 GUI 的服务器可以部署 CLI/TUI；GUI 不得标记已支持但实际缺失。

## C. 重点失败场景

- 收到 data ACK 后连接断开：确保状态机不把“已写入”错误等同于“完成持久化”。
- 发送 QUIC 写入成功后数据链路断开：应用 ACK 缺口仍触发重传。
- 同一个 file ID 重复块与后续文件旧块：不得污染目标文件。
- data worker 卡在 I/O/背压时取消：先取消，再安全 join，不能永远等待。
- Windows 文件被其它进程占用或无法 rename：不能误报成功。
- IPv6 防火墙拒绝探测：回退 IPv4，不无限等待。
- 多条 UDP 源端口的 stripe：每个 NAT 映射必须单独可达或具备经过验证的复用机制。

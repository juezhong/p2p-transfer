# p2p-transfer v0.1.1 — 首次稳定版维护更新

基于已发布的 `v0.1.0` 和已合并的 [PR #40](https://github.com/juezhong/p2p-transfer/pull/40) 修复。v0.1.0 保持不变；本次从 `main` 构建全新七平台二进制，程序内版本号为 `0.1.1`。

## 修复

- **只有发起 `put/get` 的设备可 `cancel` / Ctrl-C 结束该任务**：本地成功获取任务执行权后才允许取消；远端 Control RPC 拒绝非发起方取消，避免取消对端传输。
- **双端同步文件任务状态**：通过创建方统一裁决的 `TransferStatus` RPC，双方可看到同一任务发起设备、状态和任务编号；用户界面不再显示难懂且容易在双端不一致的「租约」。
- **退出保护**：传输期间拒绝意外 `quit/exit` 中断对端任务，同时修复被拒绝退出后的输入线程恢复。
- 保留原有认证 ICE、Control/Data QUIC、SHA-256 和递归文件/目录传输逻辑。

## 平台与校验

提供 Linux x86_64/aarch64（GNU 和静态 musl）、macOS x86_64/aarch64、Windows x86_64 共 7 个 CLI 可执行文件，附带 `SHA256SUMS.txt`；发布流水线通过 Rust 格式化、Clippy、工作区测试、七目标测试和 Release 构建后才创建 Release。

## 兼容性及已知限制

- **双方设备都必须升级到 v0.1.1**，不支持与使用旧 `v0.1.0`/test.8 的另一端混用新的任务状态协议。
- 真实 x86_64 ↔ RK3568 双机 2 GiB 全程 SHA 校验、复杂取消竞态和公网 NAT/CGNAT 验收仍待实机完成；本次自动化测试不能视为这些现场验证通过。
- 没有 TURN/Relay，也尚未完成断线未确认分块自动重传及四 Data lane 并行 striping。
- **访问权限提醒：** 在 Unix 端，可信配对设备可在本地进程权限范围内访问整个文件系统；请勿使用 root 与不可信设备配对，INVITE/REPLY 必须通过可信私密渠道传递。
